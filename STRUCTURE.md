# STRUCTURE — dirtyredz.com

## Overview

Personal portfolio site for David "Dirtyredz" McClain — game mods & servers, software
projects, and an about page. **Vite 6 + React 18 + react-router 7**, plain CSS (no
CSS framework, no state library; node:test for `src/lib` logic). Static SPA deployed on **Cloudflare
Pages** (project `dirtyredz-com`, production branch `master`: `npm run build` → publish
`dist/`, Node pinned via `.node-version`; `public/_redirects` provides the `/*` →
`/index.html` SPA fallback so React Router owns client-side routes). Production deploys
are CI-gated: the `deploy` job in `.github/workflows/ci.yml` runs after `check` on pushes to `master`
and publishes `dist/` via `wrangler pages deploy` (Pages' automatic deploys are disabled).

The distinguishing idea: the portfolio **auto-pulls itself from the GitHub API** rather
than being hand-maintained. `src/lib/github.js` fetches public repos, classifies each as
a _mod_ or a _project_ by language/keyword/topic heuristics, and caches to
`localStorage`. `src/hooks/useGithub.js` merges in hand-written entries (private/off-GitHub
work) and falls back to the curated static lists in `src/data/` when the API is
unreachable. Every page renders the same `Card` component off that one shape, declared as the JSDoc
`@typedef CardItem` at the top of `src/lib/github.js`.

## Layout

```
.                        # config + docs only (package.json, vite.config.js, .node-version, index.html, README, STRUCTURE.md, AGENTS.md, CLAUDE.md, docket.json, eslint.config.js, .prettierrc.json, .prettierignore, .editorconfig)
├── scripts/             # manual maintenance tooling (Node, run via npm scripts)
│   └── generate-fallback.mjs  # npm run gen:fallback — rewrites data/mods.js + projects.js
├── .github/workflows/   # CI + gated deploy: ci.yml (check: format:check, lint, test, build; deploy)
├── docs/                # the living-doc set (ARCHITECTURE, DECISIONS, FEATURES, ROADMAP, GOTCHAS, BACKLOG (pointer to items/)) + items/ (Docket work items)
├── public/              # served verbatim at / — fonts, img, favicon, manifest, _redirects
└── src/
    ├── main.jsx         # Vite entry: mounts <App> in <BrowserRouter>, imports global.css
    ├── App.jsx          # app shell: Nav + <Routes> + Footer, ScrollToTop on navigation
    ├── pages/           # one default-export component per route (+ its co-located .css)
    │   ├── Home.jsx/.css  About.jsx/.css  Mods.jsx/.css
    │   └── Projects.jsx  NotFound.jsx
    ├── components/      # shared UI reused across pages (each with co-located .css)
    │   ├── Nav.jsx/.css   Footer.jsx/.css
    │   └── Card.jsx/.css  # + CardSkeleton loading state
    ├── hooks/           # React behaviour, no markup
    │   ├── useGithub.js   # fetch → classify → merge manual → fallback
    │   └── useReveal.js   # IntersectionObserver scroll-in animation
    ├── data/            # content: hand-edited (site, manual) + generated fallback snapshots
    │   ├── site.js       # identity, tagline, githubUser (single source) + derived github URL
    │   ├── manual.js     # entries not in the public GitHub feed (wins on title collision)
    │   └── mods.js  projects.js   # GENERATED offline fallback lists — never hand-edit
    ├── lib/             # external-service clients + their domain rules
    │   ├── github.js     # GitHub API fetch, mod/project heuristics, overrides, cache
    │   └── github.test.mjs  # node:test: pagination (co-located; `npm test`)
    └── styles/
        └── global.css   # design tokens (CSS vars) + base/layout rules
```

**Enforced homes:**

- `src/pages/` — one route component per file, plus its co-located page CSS
- `src/components/` — shared UI reused by more than one page, plus its co-located CSS
- `src/hooks/` — reusable React hooks (data fetching, DOM behaviour); no markup
- `src/data/` — content, no logic: hand-edited `site.js` / `manual.js`, plus `mods.js` / `projects.js`, which are generated by `scripts/generate-fallback.mjs` (never hand-edit)
- `scripts/` — manual maintenance tooling run via `npm run`; imports `src/lib/` rather than duplicating its rules
- `src/lib/` — external-service clients and their domain rules (GitHub API + classification), plus co-located `*.test.mjs` (node:test, run by `npm test`; nothing imports them, so Vite never bundles them)
- `src/styles/` — global CSS: design tokens and base/layout rules
- `docs/` — the living-doc set; the repo root is config and docs only
- `.github/workflows/` — GitHub Actions workflows (`ci.yml`); config only, no code
- Root tooling config: `eslint.config.js`, `.prettierrc.json`, `.prettierignore`, `.editorconfig`
- `src/main.jsx` — Vite's mandated entry module, referenced by `index.html`
- `src/App.jsx` — router shell; the only place routes are declared

Everything else at the repo root is configuration or documentation. `public/` is served
verbatim and holds assets only, never code.

## Structural debt

**Last full review: 2026-09-17** — baseline, whole codebase. Three Claude lenses
(componentization, abstraction, topology) plus a Codex `gpt-5.6-sol` cross-model sign-off,
which returned **PASS with no P0**.

17 JS modules under `src/` plus `src/lib/github.test.mjs` and `scripts/generate-fallback.mjs`; largest is `lib/github.js` at ~264 lines (the `CardItem` typedef, fetch timeout, the `fetchLiveItems()`/`fetchRepos()` split and pagination) — nothing near the 800-line cap. No
directory holds more than 5 code files. Dependency graph verified acyclic, with nothing in
`lib/` or `data/` importing upward: `pages → hooks → {lib, data}`, plus pages → components
and pages → `data/site.js`. `lib/github.js` has one import, `githubUser` from `data/site.js` (dk-f6f1db50,
2026-10-13); `site.js` imports nothing, so the edge points downward and stays Node-safe. No other
`lib → data` edge exists. The Layout block above was
checked against the real tree in both directions and matches.

**The structure is sound.** Every deferred finding is tracked in
Docket items in [`docs/items/`](docs/items/) (`dk list`) — P0 is empty and that is the correct state. In summary:

- **P1 ×3** — the `data/mods.js` / `projects.js` snapshots were undocumented stale-tolerant
  fallbacks (dk-77bae980) — now generated by `npm run gen:fallback` (7a4e059), so they can still go
  stale between runs but never by hand-drift; the card item shape was re-asserted by four producers
  (now documented once as `CardItem`, still no TypeScript or test to catch drift; dk-788efc26); `fetchRepos` has no request timeout, so a _hanging_ GitHub
  request never reaches the fallback the way a _failing_ one does (dk-d343facb) — **fixed in 71065b6** (8 s `FETCH_TIMEOUT_MS`).
- **P2 ×2** — two earned-but-deferred extractions: `CardGrid`
  (dk-ee92652e) and `PageHeader` (dk-a5431344).

**Examined and deliberately left alone** — recorded in the watch list in `docs/DECISIONS.md` with the
trigger that would change each verdict, so a future baseline need not re-litigate them:

- Splitting `lib/github.js` into HTTP client + classifier. The two jobs are ~55 and ~65
  lines and still share the same `REPO_OVERRIDES` / `blob()` helpers, so a split today yields two
  files that always change together. Verdict kept ("not yet") at ~264 lines; revisit if the transport grows (e.g. auth or ETag). The `fetchLiveItems()` extraction (pure transport + timeout + classify + sort, under a thin cached `fetchRepos()` wrapper) is done (dk-9e99a9a0); revisit if the classifier grows materially.
- Renaming `src/lib/` to `src/github/`. The topology lens flagged `lib/` as a generic
  bucket; the Codex sign-off overruled it — the folder has a precise responsibility in the
  Layout above, and a second client is not required to justify a conventional
  external-integration boundary. Revisit when a second client appears.
- Extracting the duplicated `usingFallback` / empty-state block. Two four-line call sites;
  both the abstraction lens and Codex declined to extract at this size. Revisit at a third
  list page.
- Adding a typechecker — a decision, not an oversight (no TypeScript in the repo; rejected in the
  2026-10-15 ADR). See [`docs/DECISIONS.md`](docs/DECISIONS.md).
