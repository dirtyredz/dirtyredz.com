# `src/data/mods.js` / `projects.js` drift with nothing to regenerate them

From docs/BACKLOG.md (P1 — real debt, worth a task), originally B1.

Done. Labelling landed 2026-09-17; the regeneration script landed in 7a4e059.

These files are *failure fallbacks*, not primary content. They could drift silently from
reality, and the site serves them whenever the GitHub API fails — looking plausible while
being wrong.

**Labelling (2026-09-17).** Both files carry headers stating what they are, when they
render, and where to change real content instead. The review found the old headers were not
merely absent but *actively wrong* — `mods.js` instructed the reader to "Edit this list to
add your game mods," which is the exact misconception. The same error was in `README.md`
and was also fixed.

**Resolution: `scripts/generate-fallback.mjs` (`npm run gen:fallback`, commit 7a4e059).**
The script writes both files from a live GitHub fetch and is run manually, committed like a
lockfile. This removed the hand-drift class: the files can still go stale between runs, but
they are no longer hand-maintained.

**Consequence.** `mods.js` / `projects.js` are now generated artefacts rather than
hand-authored content. The `src/data/` mixed-content verdict was re-examined and kept; see
the watch list in `docs/DECISIONS.md` (separate only if more generated files appear).
