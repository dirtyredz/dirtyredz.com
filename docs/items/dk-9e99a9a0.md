# Split fetchRepos into a pure fetchLiveItems() and a cached wrapper


Raised by the push review on 2026-10-13 (componentization + abstraction lenses, both P2).

`fetchRepos({useCache})` in `src/lib/github.js` mixed cache policy, transport plus the 8 s timeout, classification and sorting. The `useCache:false` flag existed only so `scripts/generate-fallback.mjs` could run it in Node, relying on `readCache`'s try/catch swallowing the missing `sessionStorage`.

**Resolution (done 2026-10-13).** Extracted a pure exported `fetchLiveItems()` (fetch, 8 s `FETCH_TIMEOUT_MS` abort, classify, sort; no cache). `fetchRepos()` is now a thin browser wrapper: `readCache` then `fetchLiveItems` then `writeCache`. The `{useCache}` option is removed and `scripts/generate-fallback.mjs` calls `fetchLiveItems()`. Cache storage is unchanged (sessionStorage; localStorage is dk-517a7ebf). ARCHITECTURE, STRUCTURE, DECISIONS and GOTCHAS updated. `npm run build` and `npm run gen:fallback` pass.
